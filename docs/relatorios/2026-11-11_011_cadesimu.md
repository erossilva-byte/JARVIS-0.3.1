# Relatório — Fase 2, ajuste 011: ponte CADeSIMU e elétrica

## 1. O que já existia

- `projetista.js` — motor de projeto elétrico: interpreta o pedido, monta o circuito, valida,
  exporta netlist, gera relatório e ladder.
- `conferirTrocaCadesimu(projeto)` — checklist determinístico para levar o projeto ao CADeSIMU por
  redesenho manual. Nunca gera nem lê o `.cad` proprietário, e diz isso em `nativo: false` e no
  `aviso`.
- `exportarTrocaCadesimu(projeto)` — JSON `JARVIS-CADESIMU-TROCA` v1 com símbolo IEC, terminais,
  posições, redes e netlist.
- `tests/test_cadesimu_troca.js` — 4 grupos: projeto válido aprovado, pacote de intercâmbio,
  terminal solto reprovado e recusa de reversão trifásica em motor monofásico.

Todos passavam antes desta rodada.

## 2. Defeito encontrado: pendência sem item reprovado

Sondei o checklist com um erro de edição plausível: **o mesmo componente duas vezes**, ou seja, ID
repetido no projeto.

Reprodução, com uma partida direta trifásica de 5 CV e o primeiro componente duplicado:

```
ok = false
pendencias = ["ID repetido: F1"]
verificacoes falhas = []
todas as verificacoes ok?  true
resumo = "Faltam 1 item(ns) para o redesenho: ID repetido: F1"
```

O conjunto reprovava e o resumo dizia "faltam 1 item", mas **nenhum item do checklist estava
reprovado**. A causa: o ID repetido era empurrado direto em `pendencias` dentro do laço, sem virar
`item(...)`. Como o relatório técnico imprime o checklist (e não a lista de pendências), o usuário
lia exatamente isto:

```
   Checklist de redesenho: com 1 pendência(s)
     OK verificação estrutural
     OK todos os tipos têm símbolo mapeado
     OK todo terminal obrigatório tem rede
     ...
```

Uma pendência que não aparece é pior do que uma pendência a mais: o projeto é reprovado e a pessoa
não tem como saber por quê, nem o que corrigir.

## 3. Correção

O ID repetido passou a ser coletado e virou item próprio do checklist
(`sem ID repetido`), com o ID no detalhe. Nenhuma regra foi afrouxada: o projeto continua reprovado,
agora com a linha visível. Depois da correção, o mesmo caso:

```
   Checklist de redesenho: com 1 pendência(s)
     OK verificação estrutural
     FALTA sem ID repetido — IDs repetidos: F1
     OK todos os tipos têm símbolo mapeado
     ...
```

Fica valendo também a invariante que o defeito quebrava: **toda pendência corresponde a um item
reprovado** — contagem de `pendencias` igual à de verificações com `ok: false`.

## 4. Teste que trava o caso

`tests/test_cadesimu_troca.js` saiu de 4 para 5 grupos. O grupo novo:

- ID repetido reprova a ponte (`ok: false`);
- existe ao menos um item com `ok: false`, e o detalhe cita o ID;
- `pendencias.length === verificacoes.filter(!ok).length`;
- o relatório contém `FALTA sem ID repetido`;
- o relatório não se declara completo e reprovado ao mesmo tempo.

## 5. O que continua sem prova

- **CADeSIMU não foi aberto.** O `.cad` nativo continua não suportado: é formato proprietário, sem
  especificação pública, e não há arquivo de amostra real neste ambiente. O que está provado é a
  consistência interna do projeto e do pacote de intercâmbio.
- **Simulação elétrica não existe**: a verificação é de continuidade e de regras, não de tensão,
  corrente ou transitórios. O relatório declara isso na seção de limitações.
- **Desenho manual não foi comparado** com o resultado no programa original.
